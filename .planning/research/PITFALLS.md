# Domain Pitfalls & Mitigations

## Critical Pitfalls & Mitigation Strategies

### 1. 세션 만료 및 재로그인 처리
- **위험**: 헤드리스 브라우저가 만료된 쿠키를 사용하여 페이지에 접근하면 로그인 화면으로 리다이렉트되어 파싱 에러 발생.
- **해결책**:
  - 대시보드나 과목 페이지 로딩 후 현재 URL이 로그인 페이지인지(`login` 키워드 또는 로그인 폼 존재 여부)를 검사하는 `is_authenticated()` 헬스체크 구현.
  - 세션이 만료된 경우 저장된 `session.json`을 삭제하고 즉시 자동 재로그인을 수행하여 새 세션을 획득.

### 2. 대학 사이트 날짜/시간 포맷의 불규칙성
- **위험**: 사이트 내에서 `~ 2026.09.21 23:59`, `2026-09-21 23:59:59까지`, `09월 21일 23:59` 등 다양한 형식 혼재.
- **해결책**:
  - 정규식 기반의 다중 패턴 매칭 파서를 구축하고, 누락된 연도는 현재 연도로 자동 보정.
  - 모든 파싱된 시간은 명시적으로 한국 표준시(Asia/Seoul, UTC+9) 타임존을 부착하여 노션에 ISO-8601 형식(`YYYY-MM-DDTHH:mm:ss+09:00`)으로 전송.

### 3. 노션 데이터베이스 스키마 불일치 에러
- **위험**: Notion API는 데이터베이스 속성 이름, 타입, 옵션 값이 정확히 일치하지 않으면 400 Validation Error를 반환함.
  - 예: `상태`에 없는 옵션을 전달하거나, `우선순위`에 이모지가 빠진 텍스트를 전달하는 경우.
- **해결책**:
  - 실제 Scheduler DB의 스키마(`collection://21d53280-64be-80ec-af4e-000b679f03bb`)에 정의된 정확한 옵션 값을 상수로 정의:
    - `선택`: `루틴`, `이벤트`
    - `상태`: `시작 전`, `진행 중`, `완료`, `폐기`
    - `우선순위`: `🔴 긴급 (P1)`, `🟡 중요 (P2)`, `🔵 보통 (P3)`, `⚪ 낮음 (P4)`
    - `구분`: `학업`, `과제` 등 기존 옵션 활용
    - `DueDate`: `{"start": "YYYY-MM-DD"}` 또는 `{"start": "YYYY-MM-DDTHH:mm:ss+09:00"}`

### 4. 중복 동기화 방지 및 멱등성(Idempotency)
- **위험**: 스킬을 여러 번 실행할 때마다 동일한 인강/과제가 노션에 중복 등록되어 스케줄러가 오염됨.
- **해결책**:
  - 노션 등록 전, 해당 DB에서 현재 등록하려는 작업 이름(`이름`)과 마감일(`DueDate`)이 일치하는 레코드가 이미 존재하는지 쿼리(`filter` 또는 SQLite SQL 쿼리).
  - 이미 존재하는 경우 생성을 건너뛰고(`Skip`), 변경 사항이 있거나 미등록된 항목만 생성.

### 5. 대학 방화벽 및 요청 속도 제한 (Rate Limiting)
- **위험**: 과도한 속도로 연속 페이지 요청 시 대학 방화벽에 의해 IP가 일시 차단될 수 있음.
- **해결책**:
  - 페이지 이동 및 과목 크롤링 시 적절한 딜레이(0.5~1.5초 랜덤 지연)를 두고, 불필요한 이미지/미디어 리소스 로딩은 Playwright 라우팅 인터셉트로 차단(`route.abort()`)하여 속도와 대역폭을 최적화.
