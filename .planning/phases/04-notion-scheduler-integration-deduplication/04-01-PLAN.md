## Scope justification

This plan coordinates ten files because the tracer must prove one real configured read path through the final DTO, client, and engine seams before either expansion task runs. The ten paths form three bounded ownership clusters rather than ten independent implementation surfaces: Task 1 owns four tracer files (`models.py`, `client.py`, `engine.py`, and its engine test); Task 2 owns the four-file configuration gate and fixtures; Task 3 owns the three-file transport/error hardening cluster, with `client.py` intentionally shared with the tracer it hardens. Splitting configuration away would leave the tracer unable to represent D-07 ID/name selection or D-09 disabled behavior through the production `Settings` contract, while splitting client hardening would require a second temporary transport contract and invalidate tracer-first verification. Each task touches at most four files, has its own sub-60-second focused command, and the final Wave 1 command verifies their single atomic call sequence together; keeping them in one plan is therefore safer than introducing a partially configured or multiply revised read boundary.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local environment -> Settings | Credential and target selectors enter the process from developer-controlled runtime configuration. |
| application -> notion-client SDK | Structured target/schema/query/write requests cross into third-party client code. |
| notion-client SDK -> user-owned Scheduler | Remote data and errors cross the network boundary; a wrong target or schema assumption could affect user data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | `Settings`, client error translation | high | mitigate | Mask both credential inputs in repr/str; omit headers/request bodies from logs/results; assert known secret strings are absent. |
| T-04-02 | Tampering | `resolve_target` | high | mitigate | Give explicit ID priority, paginate and exact-match names, require uniqueness, and stop without writes on ambiguity. |
| T-04-03 | Tampering | schema preflight | high | mitigate | Retrieve and compare all eight live properties/options read-only before query/write; emit `NotionSchemaError`; provide no schema mutation method. |
| T-04-04 | Denial of Service | API request policy | medium | mitigate | Centralize 0.35-second spacing, bounded SDK 429 retries, bounded read-only 529 retries, and no replay of uncertain writes. |
| T-04-05 | Repudiation | transport failures | medium | mitigate | Preserve safe error code/request ID/target/task context in structured results while excluding secrets. |
| T-04-SC | Tampering | package supply chain | high | mitigate | Perform no install or upgrade; use the hash-locked notion-client 3.1.0 already in `uv.lock`. If dependency mutation becomes necessary, halt before package-manager execution for a blocking legitimacy review. |

Security canon breadcrumbs from the prohibition recall: credential disclosure and untrusted-text injection are owned by this STRIDE/ASVS register (and Phase 5 output escaping), so they are not duplicated as bespoke `must_haves.prohibitions`.
</threat_model>
