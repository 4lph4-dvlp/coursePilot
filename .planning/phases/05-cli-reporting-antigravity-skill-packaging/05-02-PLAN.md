<objective>
Make the collection pipeline resilient and honest: isolate per-course failures and keep going (D-08), validate LMS settings before any browser work and let config/login/course-list failures abort as fatal (D-08, D-12), fire per-course progress for stderr display (D-11), honor `--relogin` / `--headed` (D-10), and prove the real per-course scraping sequence is read-only against fixture HTML.

Purpose: Plan 05-01 proved the happy path; real LMS runs will hit restricted courses and slow pages, and SKIL-01's "빠짐없이" core value requires that one bad course never hides the others or reads as "nothing due".
Output: hardened `src/coursepilot/pipeline.py` and `tests/test_pipeline.py`. No CLI changes are needed — 05-01 already maps `result.errors` to exit 1 and escaped exceptions to exit 2 — so this plan runs in parallel with 05-03, which owns `cli.py`.
</objective>
