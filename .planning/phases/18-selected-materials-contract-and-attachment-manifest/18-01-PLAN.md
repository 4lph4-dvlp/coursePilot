## Contract proposal for the D-18-09 checkpoint

The executor must place the precise approved revision in `18-CONTRACT-PROPOSAL.md`; this is the concrete starting proposal presented for review:

| Operation | Exact flags beyond `materials --contract-version 1 --operation OP --json` | Effect |
|---|---|---|
| `manifest` | optional `--course COURSE_ID --week current|all|N` | Course pages only; each module has `attachments.completeness=unknown`, `reason=not_inspected`. |
| `inspect` | `--course COURSE_ID --module-id MODULE_ID --approve-view-effect` | One module detail visit may mark viewed. |
| `select` | `--course COURSE_ID --module-id MODULE_ID --manifest-digest SHA256 --file-id FILE_ID` (repeat `--file-id` only for additional explicitly approved files) `--approve-view-effect` and optional `--output-dir PATH` | Reinspect exact module, compare full digest, then fetch only named files. |

Bare `materials` and `files` retain existing arguments and unversioned JSON. The proposed versioned envelope has exact keys `schema_version` (integer `1`), `operation` (`manifest|inspect|select`), `status` (`ok|partial|fatal|stale|unknown`), `view_effect` (`may_mark_viewed`, `approved`, `visit_attempted`: booleans), `courses` (list, empty outside manifest), `module` (object or null), `selection` (object or null), `files` (list, empty outside select), and `error` (`{code,message}` or null). `courses[]` has `course_id`, `course_name`, `weeks[]`; `weeks[]` has `week_number`, `modules[]`; each module has `course_id`, `week_number`, `module_id`, `module_type`, `title`, `source_url`, and `attachments`. `attachments` has `completeness` (`complete|unknown`), `reason` (string or null), `files` (list) and `manifest_digest` (SHA-256 string or null). An attachment has `file_id`, `name`, `source_url`. `selection` has `course_id`, `module_id`, `file_ids` (explicit ordered list) and `manifest_digest`. Each `files[]` result has `file_id`, `status` (`downloaded|verified_existing|failed`), `source` (`course_id`, `module_id`, `source_url`, `manifest_digest`), `saved_path` (string or null), `size_bytes` (integer or null), `sha256` (string or null), and `error` (`{code,message}` or null). `unknown` cannot have a digest or selectable files. Version/shape errors stop before effects; proposed exits are 0 for success/known unknown, 1 for recoverable partial, 2 for invalid/fatal/stale. Every valid versioned result emits one JSON object on stdout.

Canonical digest proposal: UTF-8 JSON with stable key order, no whitespace, source-bound `course_id`, `module_id`, `module_type`, `source_url`, and every attachment's `file_id`, `name`, `source_url` sorted by file ID, SHA-256 hex. Another same-week module is excluded. The human gate may amend this proposal; plans 18-02 through 18-05 execute only the approved revision.
