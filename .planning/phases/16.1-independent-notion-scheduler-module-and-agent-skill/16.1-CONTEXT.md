# Phase 16.1: Independent Notion Scheduler Module and Agent Skill - Context

**Gathered:** 2026-10-03
**Status:** Ready for planning

<domain>
## Phase Boundary

기존 CoursePilot 안의 개인 Notion Scheduler 연동을 별도 저장소의 독립 패키지와 Agent Skill로 분리한다. 새 스킬은 CoursePilot 없이 학업 외 작업을 조회·생성·수정·완료 처리할 수 있어야 한다. CoursePilot은 독립 패키지를 통해 기존 학업 동기화와 시청 완료 처리를 계속 수행하며 중복 방지, 미리보기, 사용자 관리 필드 보호 동작을 유지한다. 직접 API와 공식 원격 MCP를 실제 작업 단위로 비교하되 직접 API를 기본 경로로 유지한다.

</domain>

<decisions>
## Implementation Decisions

### 독립 저장소와 CoursePilot 경계

- **D-16.1-01:** Scheduler 패키지와 Agent Skill은 CoursePilot 저장소 밖의 별도 저장소에 둔다. CoursePilot은 명시된 패키지 계약을 통해 이를 사용한다. — **Reversibility:** costly — 나중에 합치면 두 저장소의 배포 및 의존성 경로를 다시 바꿔야 한다.
- **D-16.1-02:** CoursePilot의 LMS 수집, 학업 작업 이름·우선순위 계산, 영상 시청 완료 판단은 CoursePilot 책임으로 남긴다. Scheduler 접근과 일반 작업 관리는 독립 패키지 책임으로 옮긴다.
- **D-16.1-03:** 새 저장소의 이름 `notionScheduler`는 가명이다. 최종 저장소·패키지·스킬 이름은 계획 과정에서 일관되게 정한다.

### 독립 스킬의 첫 버전

- **D-16.1-04:** 학업 외 Scheduler 작업에 조회, 생성, 수정, 완료 처리를 제공한다. 삭제와 보관은 첫 버전 범위에서 제외한다.
- **D-16.1-05:** 독립 스킬은 사용자가 명시적으로 요청한 경우 `Plan`과 `상태`를 수정할 수 있다. CoursePilot 자동 동기화에서는 두 필드를 계속 보호하며, 기존의 명시적 시청 완료 처리 동작은 유지한다.

### Notion 접근 방식과 검증

- **D-16.1-06:** 직접 Notion API 호출을 대량 동기화와 일반 Scheduler 작업의 기본 실행 경로로 유지한다. 공식 원격 MCP는 선택 경로로 제공한다.
- **D-16.1-07:** 대표적인 조회·생성·수정 시나리오에서 API와 공식 원격 MCP의 기능, 모델 토큰 사용량, 도구 호출 수, 소요 시간을 측정한다. 결과를 기록한 뒤 기본 경로 변경 필요성을 재검토하며, 추정 절감률을 실측값으로 제시하지 않는다.

### 실행 순서와 후속 검증

- **D-16.1-08:** Scheduler 분리를 기존 Phase 17의 CoursePilot 스킬 재배포·E2E 검증보다 먼저 진행한다. Phase 17은 새 패키지 연동과 스킬 사용 경로를 반영하도록 계획을 갱신한다.
- **D-16.1-09:** 2026-10-04 사용자 후속 결정. 개인 Scheduler에서 `선택`을 의도적으로 삭제하고 `tag` 다중 선택을 추가했다. 독립 스킬과 CoursePilot은 현재 개인 DB를 기준으로 맞춘다. `tag` 값은 명시적 일반 작업에서만 변경하며 학업 자동 동기화는 보존한다.

### the agent's Discretion

- 독립 패키지의 내부 모듈 구성, CLI 세부 명령과 JSON 계약, 충돌 없는 일반 작업 식별 방식.
- 별도 저장소의 최종 이름과 로컬 경로. 단, 사용자가 `notionScheduler`를 가명이라고 밝혔으므로 이름을 확정된 요구사항으로 취급하지 않는다.
- 비교 실험의 샘플 크기와 계측 도구. 실제 Scheduler 쓰기는 검증 범위와 승인 조건을 별도로 따른다.

</decisions>

## Existing Code Insights

### Reusable Assets

- `coursepilot.notion.client.NotionClient`: SDK 전송 경계, 페이지 순회, 요청 간격 조절과 오류 변환.
- `coursepilot.notion.mapper`, `deduplicator`, `engine`: 스키마 검증, 순수 변경 계획, 미리보기 및 실행 분리.
- 현행 Notion 단위·통합 테스트: 분리 전후 동작 비교에 사용할 수 있다.

### Established Patterns

- 기본 `sync`는 드라이런이고 실제 쓰기는 명시적 적용 경로로만 수행한다.
- LMS 자동 동기화는 `Plan`과 `상태`를 보호하고, 출처·제목이 모호하면 변경을 건너뛴다.
- 에이전트는 CoursePilot CLI의 버전 명시 JSON 결과를 읽고 사용자에게 요약한다.

### Integration Points

- `src/coursepilot/cli.py`의 동기화 및 `watch sync-notion` 경로.
- `src/coursepilot/player/runner.py`의 시청 완료 갱신 경로.
- `src/coursepilot/config.py`, `pyproject.toml`, `skills/coursepilot/SKILL.md`의 설정·의존성·스킬 지침.

## Specific Ideas

- 독립 스킬은 CoursePilot 없이도 개인 Scheduler에 학업 외 작업을 관리할 수 있어야 한다.
- 사용자는 API 방식의 토큰 절감 효과가 실제로 큰지 궁금해하며, 공식 원격 MCP의 현재 기능과 실측 비교를 원한다.
- 기존의 학업 Scheduler 항목과 사용자 관리 `Plan`·`상태` 값은 분리 과정에서 유지되어야 한다.

</specifics>
