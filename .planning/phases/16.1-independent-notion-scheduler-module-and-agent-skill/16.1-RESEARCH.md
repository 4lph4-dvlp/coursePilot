# Phase 16.1 Research: Independent Notion Scheduler

## Decision

Create a sibling Python repository containing a Scheduler API package, a small JSON CLI, and an agent skill. Keep CoursePilot's LMS extraction, naming, priority calculation, source identity, and sync decisions in CoursePilot. Move the Notion transport, Scheduler schema, page parsing, and general task operations to the new package. Use direct Notion API as the default transport. Let an agent use the official remote MCP as an optional interactive route; do not make unattended CoursePilot sync depend on MCP OAuth.

## Evidence

- Current `coursepilot.notion.client.NotionClient` resolves a data source, validates schema, paginates filtered rows, throttles requests, and writes page properties through `notion-client`. `mapper.py` holds the eight-field Scheduler contract; `deduplicator.py` contains LMS-specific matching and belongs in CoursePilot.
- Hosted Notion MCP uses OAuth and currently requires interactive authorization, so an unattended job cannot rely on its connection. [Notion connection guide](https://developers.notion.com/guides/mcp/get-started-with-mcp)
- `notion-query-data-sources` rows mode returns at most 100 rows and no cursor; plan access can be metered. Saved view mode supports a cursor. The REST data-source query used by the current SDK supports pagination. [MCP supported tools](https://developers.notion.com/guides/mcp/mcp-supported-tools)
- Remote MCP can batch page creation and return compact Markdown or projected SQL results. Its agent friendliness does not by itself establish lower model-token use for Scheduler sync. [MCP supported tools](https://developers.notion.com/guides/mcp/mcp-supported-tools)

## Read-only probe, 2026-10-03

The existing API client resolved the target and read 91 recent or incomplete rows in about 2,048 ms. An official remote MCP SQL query with a comparable date/status filter returned 91 rows in about 1,039 ms and 15,374 text characters. These are single observations with different setup and output paths. They are neither a controlled latency comparison nor a token measurement. The local API integration and remote OAuth connection have different access scopes. Do not infer a token-saving percentage.

## Validation Architecture

Use fake-SDK unit tests for target resolution, schema checks, pagination, sparse property updates, ambiguous identity, and preview isolation in the sibling package. Run CoursePilot's Notion and watch regression tests after the adapter migration. Validate the JSON CLI and packaged skill examples against the implemented parser. Keep live comparison in a disposable target under a separate approval checkpoint; never treat a simulated write as measured remote MCP write performance.

## Architecture and validation

1. Publish a stable `notion_scheduler` Python interface and JSON CLI with explicit read, create, update, and complete operations. Keep deletion and archive out of scope. Validate schema before writes; require page ID or an unambiguous lookup for updates. Accept explicit changes to `Plan` and `상태` only in user-requested general operations.
2. Keep CoursePilot's `NotionSyncEngine` and deduplicator as policy adapters. Migrate transport and common mapping to the external package through a compatibility facade, preserving dry run, duplicate handling, protected fields, and watch-completion behavior. Avoid implicit live writes during migration tests.
3. Package an agent skill that uses the JSON CLI by default and documents the official remote MCP as an optional interactive route. The skill should preview changes and request explicit execution for writes.
4. Test the new package with a fake SDK and CoursePilot with existing Notion tests plus focused integration checks. Use a controlled benchmark harness with identical scenarios and record model usage, tool calls, and elapsed time when both connections and usage counters are available. Keep observed numbers separate from estimates and record missing measurements honestly.

## Risks

- A local sibling path dependency works for development but needs a distribution strategy before Phase 17 agent deployment. Keep versioned package contract and document installation.
- Existing `.env` points to a data-source name; the ROADMAP identifier may denote the data source rather than the database container. Continue resolving target via the existing path; do not assume the IDs are interchangeable.
- General task edits can overwrite user fields if update payloads are not sparse. Verify that omitted properties remain unchanged and automatic sync never updates `Plan` or `상태`.
