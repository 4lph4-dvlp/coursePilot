<objective>
Implement advanced VOD player controls, playback resilience, and lifecycle management:
1. Precision targeting with video index filtering (`--video-index N`, D-12-02) and fuzzy course name resolution (`find_target_course`, D-12-03) while maintaining 1.0x sequential playback (D-12-01).
2. Playback resilience in `VodPlayer` (15s stall detection with 3x play retry and reload fallback D-12-09, sleep recovery D-12-10, and Moodle session expiry recovery D-12-11).
3. Real-time state tracking file (`watch_state.json`, D-12-04) and completed history storage (`watch_history.json`, D-12-07).
4. CLI execution lifecycle commands: non-disturbing progress query (`watch status [--json]`, D-12-05), clean process termination (`watch stop [--json]`, D-12-06), and retroactive Notion completion synchronization (`watch sync-notion [--course <name>] [--json]`, D-12-08).

Purpose: Satisfy the user's specific interactive requirements: pinpoint video selection (e.g. "기초전자정보실험 2주차 2번째 영상"), mid-playback progress queries ("지금 얼마나 봤어?"), cancellation ("시청 멈춰줘"), and retroactive Notion sync ("아까 본 거 노션 완료 처리해줘").
</objective>

    1. In `src/kau_assistant/player/vod_player.py`:
       - Strict 1.0x playback rate enforcement (D-12-01): ensure default playback rate remains 1.0x with no multi-rate bypass.
       - Implement stall detection & retry (D-12-09):
         - Track `last_progress_time` and `last_current_time`.
         - If `current_time` does not advance for >= 15 seconds while `is_paused is False` and not near end:
           - Attempt `video.play()` evaluation up to 3 times (with 2s intervals).
           - If 3 play attempts fail to resume playback, trigger `page.reload(wait_until="domcontentloaded")`.
           - Ensure the existing dialog handler (`page.on("dialog", ...)`) automatically accepts any Coursemos "이어보기(Resume from last position)" confirmation dialog.
       - Implement sleep recovery (D-12-10):
         - Avoid relying solely on monotonic wall-clock elapsed time for video termination; use DOM `currentTime` and `v.ended` as the primary ground truth.
         - If wall-clock elapsed jumps by an unexpected duration (e.g. system sleep/wake), re-evaluate DOM `currentTime` and verify video is still actively playing.
       - Implement session expiry redirect recovery (D-12-11):
         - During the polling loop, check current `page.url`.
         - If redirected to `/login/` or `/user/login.php` (Moodle session expired), call `SessionManager.ensure_authenticated(page)` to re-authenticate, then re-navigate to `vod_url` and resume playback.
  </action>
  <acceptance_criteria>
    - D-12-01: `VodPlayer` maintains 1.0x playback rate standard.

    - D-12-10: `VodPlayer` checks DOM `currentTime` and session state for sleep recovery rather than terminating purely on wall-clock time.
